# OURSELF Ecosystem Runtime Storage Symmetry Map v0.1

## One contract, multiple realizations

OSOS governs constitutional identity, authority, jurisdiction, conformance and continuity.
OURDATASELFBASE governs canonical payload objects, envelopes, journals, retention, replication and custody declarations.
OURPROCESSORSELF evaluates storage contracts and executes only admitted adapter operations.
FLOWACTIONSELFWORK orchestrates validation, provisioning proposals, replication, recontact and evidence receipts.
ALTONUMBUSELF binds memory objects to DATASELF without owning the storage substrate.
ÆTHERNET transports replication and later-runtime recontact.
SELFPI is the intended identity/admission/witness trust function; its independent custodian and admission are not assumed.
Application, browser, model, VM, container, mobile and cloud runtimes consume adapters; none owns canonical authority by virtue of hosting data.

## Universal runtime registration

Every runtime instance is registered separately. Runtime family names are not runtime identity. Each registration binds runtime ID, instance ID, host ID, failure domain, adapter ID/version, implementation digest, capabilities, durability, jurisdiction, evidence, admission and revocation.

## Storage topology

Canonical payload objects and append-only journals are authoritative. Local caches, indexes, graph projections, databases, browser storage, container volumes, model memory and application-specific stores are adapters or projections with explicitly bounded guarantees.

## Migration

Storage migration is copy-verify-recontact-admit, never copy-and-delete. Source remains available until destination evidence and a separately authorized retirement transition are complete.
